# Plugin ecosystem capability matrix

This is a local runtime, management and interactive-content implementation, a first-version distribution solution using app-shipped official listings and user-added community sources. It does not require an operated submission/review/rating service. [Validation](validation.md) distinguishes implementation from native/platform acceptance.

| Capability | Implemented locally | Partial, absent or not yet accepted |
| --- | --- | --- |
| Code plugins | One bundled JavaScript entry in an isolated Worker; brokered metrics, storage, notifications and approved HTTPS | No arbitrary Node/DOM, dynamic modules or service credential onboarding |
| Data reuse | Shared host-source sampling; a plugin's metrics reused across its views/background checks | No public inter-plugin dependencies or package dependency resolver |
| Main App, tray, Edge Dock, Notch | Placement controls, compact/full layouts, tray bitmap drawing, unified built-in/plugin Notch selection where pages beyond the left lane continue to the right of the camera and in-track arrows appear only when both sides are full | Native menu-bar interaction, Notch hover/geometry and Edge hover-card acceptance remain open |
| Optional main-app pages | Author declares `page`; user enables each page independently. Enabled pages join the existing main-app view menu, retain controls/drafts while switching, and suspend demand behind Settings. Optional detached windows share demand safely | No automatic page generation. Authoring layouts still requires a manifest/code; no visual page builder. Unsubmitted drafts and scroll are session-local |
| Free drawing | Validated rect/circle/line/arc/poly/path/text lists from plugin code; host-owned SVG/canvas rendering | Pointer/keyboard actions and persistent Sketch Pad implemented; compact declarative surfaces remain bounded; rich browser content is supported inside authored main-page, Notch and Edge Dock documents |
| Plugin identity icons | Author-supplied bounded static PNG embedded in manifest/catalog metadata; host slots in installed/catalog/detail/preview, fallback icons, no remote image fetch | Identity art stays static PNG; rich web documents can load their own package-local assets. Identity art never replaces host source labels |
| Skins | Colour/vendor presets plus font, spacing, corners and panel tokens; defaults follow App appearance, legacy overrides are read-only | Partial: finite host styles; no arbitrary stylesheets, visual layout designer or main-app shell replacement |
| Number motion | Existing App Roll and Count shared by plugin numeric components; author per-component `inherit` / `none`, default inherit; global reduced motion wins; compact rail display font matches built-in content | Authored web documents use browser CSS/Canvas animation independently of data cadence. Declarative drawing updates remain coalesced at 250 ms; authored compact rail art animates locally in Chromium and tray stays static |
| Non-AI sources | Shared total/per-core CPU, detailed memory, Linux IO rates, supported battery power state, explicit unsupported readings | GPU/temperature, pressure and additional platform IO adapters are not fabricated; service authentication not included |
| Visibility/background | Explicit background opt-in, shared demand/cadence, idle teardown, request cancellation, alert producer demand, safe mode | Sampled resource bounds; idle timers may continue until teardown; endurance unverified |
| Installation | File/folder import, package preview, exact source/version/hash, disabled until consent, staged transaction | Single-bundle `.tmplugin` format; no npm/Git package resolver |
| Updates | Manual catalog refresh, version/changelog selection, confirmation, no silent permission expansion | No automatic updater or data migration framework |
| Rollback/uninstall | One verified compatible previous version; corrupt-current rescue; data/placement retention choices; grants removed | Data migrations cannot be reversed; applied colours intentionally remain; power-loss durability not verified |
| Official catalog | Searchable offline app-shipped catalog: System Monitor, Token Pulse and Sketch Pad | Public hosting, submission, maintenance and publishing service absent |
| Community catalog | User-added HTTPS catalogs, searchable listings, cached offline metadata, explicit refresh, digest checks, Unreviewed label; optional key pin | No pre-enrolled external catalog; public registry inventory, submission, moderation, reporting/revocation operations absent |
| Evidence | Full verify, actual Electron adversarial probes, independent review rounds, real desktop renderer captures and lifecycle acceptance | Windows/Linux, packaged/signing delivery, OS notification delivery and native interactions above remain unverified |

## Author extension boundary

Original model, tool and device pages can opt into a plugin's before/after panel or replacement content. The host keeps navigation and the App-default restore choice. Packaged web documents use a separate sandboxed WebContentsView, local assets, permissioned snapshots/subscriptions and bounded storage; see [the contract](author-ui-options.md). Tray keeps its static bitmap renderer. Notch pages and Edge Dock full/compact plugin views can additionally host isolated authored documents; the declarative renderer remains the fallback. Rail art preserves host mouse gestures, while full documents support interaction.

Native focus/IME, packaged cross-platform delivery, accessibility tools and endurance still need separate acceptance. A visual page builder and inter-plugin dependency resolver are not required for this version. The shipped official catalog plus user-added HTTPS sources is the first-version distribution model; submission systems, staff moderation, ratings and remote revocation are not merge gates. No external source, registry or package is published by this work.
